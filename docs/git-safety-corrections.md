# Git safety corrections after functional review

## Supersedes earlier completion claims

Earlier clone/line-stage/push-signing/recovery/signature/image reports overstated safety or coverage. Green tests did not prove user intent or even actual image activation. This report supersedes conflicting statements in those reports. Not all Git functionality is complete.

### Corrected behavior

- **Line staging/unstaging:** select both +/- changes individually; preserve unselected source-side lines as context and omit unselected destination-side changes. Recompute offsets after omitted edits. Explicit active-empty, duplicate, cross-hunk, malformed or mixed hunk/line intent refuses without whole-file fallback. Missing-newline-marker partial edits deliberately refuse. UI starts with empty selections and labels changes with bounded literal text. Regression tests verify exact index bytes after add-only/delete-only partial replacements and unstage, plus unchanged workfiles.
- **Clone:** pre-cancel refusal; no existing destination, including dangling symlink/empty-folder collision; atomic create_dir reservation, --no-local/--no-recurse-submodules/--template= and checkout-filter gate. Partial reserved folder is retained on failure, never auto-deleted. Trusted Git/credential config and filesystem/config races remain, not a sandbox. Destination remains inside current project; selecting an arbitrary parent/opening cloned project still needs UX work.
- **Recovery restore:** separate worker review freezes current target bytes/mode, recovery bytes/content+path hash, real repository index location and index bytes. Confirmation applies only that review. Refuses stale target/index/recovery or symlinked parent, preserves current target content in another create-only recovery copy before replacement, retains permissions and index. Correct worktree index.lock instead of hardcoded .git/index.lock. No per-frame recovery existence IO. Owner/hide/read-only cancels pending restore intent. Backup history/list/view/delete/retention UI remains incomplete.
- **Passive signature display:** `%G?` and `%GS` CAN invoke external verification helpers; previous 'no helper' assertion was false. Passive History now uses --no-show-signature and bounded raw commit-header inspection, reports only signature-present/unverified. A signed-object test with a configured marker verifier proves no execution. Explicit real cryptographic verification/trust UI is still open; no green/trusted claim from header presence.
- **Image diff:** fix loading flag preventing worker startup. Read and decode off-thread, bounded encoded reservation plus two shared CPU/GPU leases, consume pixels on one-time texture upload, propagate failures, handle absent before/after side, refuse symlink/submodule tree entries. Include immutable object/parent/root/owner/path in control identity and route keyboard input. Real activation test verifies worker delivery, decode, texture reuse and lease release. No physical-pointer/screens/accessibility claim.
- **Signed Push:** freeze/revalidate bounded effective signing configuration with destination review. Actual signing happens during Git network negotiation, not in the previous config-read 'availability check'. UI now labels timeout as whole signed-push cap; process deadline is min(push timeout,signed timeout). No independent signer-only timeout, actual successful certificate/trust proof, or server verification claim. --signed=yes still has no unsigned fallback. Server may refuse signing support before invoking signer; old unsigned-success/signed-failure test does not prove signer execution.
- **Publication:** rejected speculative post-publication failure readback. Successful CAS must not be converted to ordinary commit failure merely because later observation fails; no new duplicate-retry risk added. Existing atomic CAS does not constitute full porcelain/reference-hook lifecycle support.
