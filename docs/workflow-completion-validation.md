## Slice 2: durable linear execution, background controls and practical delivery

### Implemented production paths

- `environment.rs` classifies specific unsuccessful tool diagnostics, not arbitrary substrings. Assertions and missing relative/absolute source imports stay implementation failures; genuine tool/package/cache failures stop safely. Typed completion policy distinguishes repair exhaustion, failed recovery/review, missing behavioral evidence, prerequisites, cancellation and uncertainty. Supplied approved plans no longer show acceptance as unstarted.
- `store::history` safely reads bounded regular files, preserves invalid/oversized/symlink records untouched as per-record quarantine, and deterministically selects the newest 1,000 valid records. UI warns about quarantine and omitted older records. No history deletion is used to regain capacity.
- Version-1 semantic operation receipts record input hashes and correlation before provider prompts/commands. An acknowledged compare-and-save precedes dispatch; only correlated results complete receipts. Unknown effects after cancellation/restart block replay. Failed/lost acknowledgments release/reconcile authoritative state instead of blindly saving a speculative record. Store saves sync both the record and directory. This is an incremental core under the existing supervisor, **not** a complete rendering-independent reducer/effects rewrite or exactly-once guarantee.
- `pui_workflow` now requests a persisted background handle. Owner-only `pui_workflow_control` supports status, event-driven wait, boundary pause, cancel and a request for fresh native continuation review. Wait timeouts/cleanup do not cancel the workflow; closing the completed start tool does not stop it. A native ownership query gates possibly-effectful parent tools after reload and native continuation, not just while extension memory remembers a handle. It conservatively serializes the window, not merely changed paths; external editors/processes and already-running independent tools are not locked or sandboxed.
- Continuation persists new consent, rechecks owner/session/permissions and source, and permits only never-started checks or a new read-only review of completed passing checks. No interrupted builder/check replay, failed-check retry, implicit setup/apply, repair-budget reset or automatic repair. Pending cancellation and failed/lost acknowledgments reconcile without blind writes. Existing explicit check-rerun and first-builder recovery remain separate.
- Builders can request four frozen-criterion checks per attempt using `pui_run_check`. A separate no-model process executes the exact command with ordinary permissions, fingerprints before/after and returns bounded feedback to the waiting builder. Feedback is separate from final acceptance evidence; final independent checks/review still run.
- Version-1 repository-root `pui-workflow.json` profiles provide bounded steps/checks and optional setup suggestions. Native consent displays identity/digest/commands and invalidates on profile drift; setup needs its own exact-command authorization. The immutable receipt is retained on the task. This is a reusable **linear verified-change recipe**, not arbitrary graphs/templates or a dependency installer.
- Selected catalog-model policy is the extension default: no router/substitutions, unique available selected model, context floor, finite positive known prices, known exceptional tiers excluded, frozen provider catalog checked at launch. Legacy dynamic/pinned requests retain their semantics. Pi confirms model/provider/effort before prompting. Actual tool/effort capability metadata, free/unknown-price policy and estimated-cost reservations are **not implemented**.
- Filesystem/Git preparation jobs have cancellation and bounded supervised subprocesses/deadlines/output; fingerprint/snapshot loops check cancellation. No unmanaged agent launcher was added.
- Apply-back creates missing ordinary nested directories with intent/identity receipts and conditional rollback. External contents and index stay intact; uncertain/replaced directories require inspection, not destructive cleanup or replay. Partial mkdir/pre-publication failures can leave retained empty directories and journals; there is no automatic recovery of unacknowledged directory creation. Existing ASCII/text/mode restrictions remain.
- Worker capacity counts unfinished children, not retained history. Bounded restoration preserves unloaded records in persistence and reserves their IDs so new workers cannot overwrite them. Existing concurrency limits remain unchanged.
- Supporting validation fixes: one unused test binding removed; `header_with_read` groups its added/removed arguments without a lint suppression; commit inspection resolves the same six Git-owned metadata paths in one validated invocation instead of six while retaining the three-second production deadline. Shared subprocess timeout text no longer falsely hard-codes three seconds for longer workflow jobs. No timeout/assertion/test exclusion was relaxed.
